# 前提

**コードは実機で一度も動いていない。** 一気に飛ばすと、どこが悪いのか
切り分けられない。プロペラを付ける前に机上で確認できることを全て潰す。

# 段階 0: デバイスの同定（毎回）

```console
$ pio device list
```

**MAC (`SER=`) を確認する。** StampFly は `48:CA:43:B6:59:C0`。
Stack-chan (`44:1B:F6:DF:59:68`) と VID:PID が同じで区別できない。
詳細は [[flashing-device-identification]]。

# 段階 1: プロペラを外して机上（最優先）

## 1-1. センサーが応答するか

シリアルに出る ID を見る。

| 期待 | 意味 |
|---|---|
| `BMI270 : OK (ID 0x24)` | IMU が応答 |
| `PMW3901 : OK (ID 0x49)` | **v1.1 に載っていることの確定** |

**PMW3901 が NG なら**、v1.1 で撤去された可能性が現実になる。
[[stampfly-spi-pinout]] の「未確定」の項を確定に更新し、
ポジションホールドは諦めて高度ホールドまでに切り替える。

## 1-2. ループが 400Hz に間に合っているか

CSV の `max_us` を見る。**2500 を超えていたら間に合っていない。**

超えていたら `platformio.ini` の `-O0` を `-O2` に変える。
それでも超えるなら制御周期を 250Hz（4000us）に落とす。
詳細は [[position-hold-design]] の「制御ループ」。

## 1-3. IMU の軸と符号

機体を手で動かして、CSV の値が期待通りに動くか見る。

| 動かし方 | 期待される変化 |
|---|---|
| 静置 | `az ≈ +9.8`、`ax, ay ≈ 0`、`gx, gy, gz ≈ 0` |
| 機首を上げる | `pitch` が **正** に増える |
| 右に傾ける | `roll` が **正** に増える |
| 上から見て右回し | `yaw_rate` が **正** |

**一つでも符号が逆なら、そこで止める。** 符号が逆のまま飛ばすと
正帰還になり、離陸した瞬間に裏返る。
`attitude.h` の `_Attitude_chipToBody()` を直す。

## 1-4. ジャイロバイアスの較正

起動後 2 秒静置して、較正が完了する（LED が変わる）ことを見る。
`Attitude_getCalibrationProgress()` が 1.0 になる。

**較正をやり直し続けるなら**、機体が動いているか振動源がある。
`ATTITUDE_CALIB_MOTION_LIMIT` が厳しすぎる可能性もある。

## 1-5. 姿勢推定の追従

- ±30° 傾けて、角度が追従する
- 戻すと 0 に収束する（数秒以内）
- **5 分放置してドリフトしない**（ヨーは除く）

収束が遅ければ `ATTITUDE_TIME_CONSTANT` を短く、
振動が乗れば長くする。

## 1-6. Optical Flow の軸

机の上で機体を滑らせ、`dx`/`dy` の符号を記録する。

| 動かし方 | 期待 |
|---|---|
| 前に滑らせる | 一方向に一貫した符号 |
| 右に滑らせる | もう一軸が動く |
| 無地の机 | `SQUAL` が低い（LED が黄） |
| 新聞紙・カーペット | `SQUAL` が高い（LED が緑） |

**符号が設計と逆なら** `position.h` の変換で吸収する。

## 1-7. ToF の距離

既知の距離（定規で測る）と比べる。5〜100cm で誤差 ±3cm 以内。

**値が変わらない / 常に同じ**なら、割り込み極性を疑う
（[[position-hold-design]] の ToF の項）。

## 1-8. 安全装置

**プロペラを外したまま**確認する。

- 起動直後、スティックを動かしてもモーターが回らない
- 較正が終わるまでアームできない
- アームするとモーターが回り始める（音で分かる）
- **JoyStick の電源を切ると 300ms 以内に止まる**
- 機体を 60° 以上傾けると止まる
- ディスアーム操作がいつでも効く

**一つでも通らなければプロペラを付けない。**

# 段階 2: テザーで初飛行

プロペラを付ける。**糸を機体中央に結び、手で持つ。**

- クッションの上
- 人は 2m 以上離れる
- 保護メガネ

## 2-1. 姿勢制御（二十八歩）

スロットルをゆっくり上げ、浮く直前で止める。

- 水平を保とうとするか
- 発振（小刻みな振動）が出ないか

**発振したら** `PID_RATE_*_KP` を下げる。
**ふらつくなら** 上げる。CSV を見ながら少しずつ。

## 2-2. 高度ホールド（三十歩）

50cm を目標に、±5cm で保てるか。手で押し下げると戻るか。

## 2-3. ポジションホールド（三十四歩）

**模様のある床**（カーペット・新聞紙）の上で。

- 1 分ホバーして目印から ±20cm 以内
- 手で 30cm 押すと元に戻る

**流れていくなら** Flow の軸か回転成分除去の符号を疑う。
**傾けただけで動くなら** 回転成分除去が効いていない。

# ToF が動かなかった場合

**ToF はポジションホールドの前提でもある。** Optical Flow の移動量[px]を
速度[m/s]に直すには高度が要るため（同じ流れでも高いほど実距離が大きい）、
高度が取れないと位置制御そのものが成立しない。

本リポジトリの ToF 実装は **VL53L1X 流の最小実装**で、参照実装（ST の
巨大 API を使う）とは方式が違う。設定ブロック 91 バイトは
「VL53L1X ULD の既定値」であって参照実装から取ったものではないため、
**ここが実機で動かない可能性が最も高い。**

## 段階的な切り分け

1. **モデルIDが読めるか** — `0x010F` が `0xEACC` を返すか。
   返らなければ I2C 配線かアドレスの問題（XSHUT が効いていない可能性）
2. **ブート完了するか** — `0x00E5` の bit0
3. **距離が変わるか** — 手をかざして値が動くか。
   **常に同じ値なら割り込み極性を疑う**（`0x0030` の bit4）

## 動かなかったときの選択肢

| 案 | 内容 | 代償 |
|---|---|---|
| A | ST の BareDriver を移植する | 3万行増える。「ゼロから書く」方針に反する |
| B | 気圧センサ(BMP280)で代用 | 室内の分解能が数十cmで高度ホールドに足りない |
| C | **高度を固定値にして Flow だけ試す** | ポジションホールドの精度は出ないが、回転成分除去の検証はできる |
| D | 高度ホールドを諦め、手動ホバリングまでとする | 二十八歩が到達点になる |

**C を勧める。** `Position_update()` に渡す高度を手で測った固定値
（例: テザーで 0.5m に保つ）にすれば、Flow の軸・符号・回転成分除去を
実機で確認できる。ToF が直った時点で本物の高度に差し替えればよい。

# ゲインの詰め方

内側から外側へ。**外側を触る前に内側を安定させる。**

```
角速度PID → 角度P → 高度PID → 速度PI → 位置P
```

CSV ログを取り、目標値と実測値の位相を見る。
遅れているなら P を上げる。振動するなら下げる。

**一度に一つだけ変える。** 複数変えると何が効いたか分からない。
